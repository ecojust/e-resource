# 用户请求与开发记录

本目录用于跨会话持续开发。接手先读 [INDEX.md](INDEX.md) 和相关任务，再核对 Git、制作队列与当前代码；上海建模入口见 [CONTINUE-SHANGHAI.md](CONTINUE-SHANGHAI.md)。长期规则放在根 [AGENTS.md](../AGENTS.md)。

## 记录约定

- 文件名为 `YYYY-MM-DD-NNN.md`，日期使用 UTC，同日序号从 `001` 递增。同一持续任务可跨日期追加；独立新请求新建记录并登记索引。
- 从本目录建立起保留每条可见用户 prompt 原文及顺序；后续补充不覆盖此前请求。历史摘录标明范围，原文不可得时直接说明，不编造。
- 状态使用 `in_progress`、`paused`、`blocked`、`completed`、`cancelled`。`paused` 表示因任务切换暂未继续，注明恢复位置；`blocked` 写明实际缺项。`completed` 只表示该次请求的目标完成，不代表上海全部建筑已完成，也不因提交了草稿就把模型任务标成完成。
- 行动记录保留实际动作、涉及文件、必要命令、结果、简短依据及证据链接。计划、执行中、失败和通过分别写明；发现旧结论错误时追加更正。
- 每个有意义阶段后，以及暂停、交接和最终回复前同步任务记录与索引。多人并行时由主 agent 汇总，其他 agent 报告各自改动与真实检查范围。
- 持久证据用仓库相对链接或具体提交链接；详细模型证据留在 `projects/shanghai/data/audit/<delivery>/`，这里只引用。临时缓存路径标明“后续环境可能不存在”。
- 不为记录新增审批流程；按照当前用户授权继续。不要把“已写代码”“已验收”“已提交”“已推送”“公开地址已验证”混为一个状态。
- 不保存秘密或私有推理。prompt 中秘密用 `[已脱敏：类型]` 替换并注明；无需转储全部工具输出。
- 日志不写自己的未知提交号。提交后可用 `git log -- history/<record>.md` 找到确切提交；如需要补充发布结果，另作记录提交，避免反复改写产生自引用。
- 新请求切换工作重点时，在新记录保留新原话，同时给旧任务追加暂停与关联记录；不把新请求当作之前模型已经结束。索引和接续入口写清“先恢复哪一项”，不能只照队列中下一个 `identity_review` 开始。
- 提交全部本地改动可以保存尚未验收的工作；记录实际包含范围、最后通过的检查和待生成报告。区分公开基线、当前开发目录和工作区增量，不从README入口数推导已经发布的数量。

## 任务模板

```markdown
# YYYY-MM-DD · 任务名称

- 状态：in_progress
- 分支：实际分支
- 起点：实际提交 SHA
- 关联记录：无／相对链接
- 本次范围：用户目标与本次边界

## 用户 prompt

### U1

> 可见原文，保持顺序；秘密按规范脱敏

## 行动记录

### A1 · 阶段名称

- 动作与文件：实际改动。
- 依据摘要：可复查的选择理由。
- 验证与结果：实际命令、结果和计数；未运行项明确说明。
- 证据：持久文件／提交链接，临时证据另行标注。
- 限制与待办：尚未完成的具体部分。

## 当前交接

- 已完成：已核实结果。
- 正在进行／阻塞：实际状态。
- 下一步：可直接执行的步骤。
- 提交／发布：分别注明本地、提交、推送、公开验证状态。
- 进度：本次影响的计数；不适用则写“不改变模型数量”。
- 恢复前置：核对当前HEAD、资产哈希、脚本基线和依赖；未产生的证据明确写“待生成”。
```

`INDEX.md` 每行至少包含记录链接、状态、用户目标、当前结果与下一步。已有 `CURRENT_STATE.md`、`DELIVERY_HISTORY.md` 和各轮 audit 保留原样，不搬运成重复的大日志；新目录从建立日开始连续记录。
