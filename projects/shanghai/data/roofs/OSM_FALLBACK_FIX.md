# 备用建筑遮挡修复

公开预览曾在Overture服务不可用、切换到OSM建筑时，出现在线平顶体块覆盖本地斜屋顶和外滩窗洞的问题。正常Overture路径通过GERS对象ID隐藏对应在线体块；原备用路径却使用MapLibre的within表达式检测建筑多边形，而当前引擎仅支持点与线，导致条件无法隐藏这些建筑。

现在备用路径读取当前已加载地图瓦片的实际OpenMapTiles建筑要素ID，再写入独立的feature-state。这些ID可能合并多栋建筑，不等于原始OSM way ID。普通分块使用原始归属格范围；精细建筑未加载或不可见时，其保留区域阻止普通分块代为隐藏备用建筑。相关精细建筑与普通分块都可显示后，可以共同覆盖同一个组件。没有扩大模型尺寸或加入任意缓冲圈。

MultiPolygon按独立Polygon组件检查：已覆盖组件由本地模型接管，其余组件以原始坐标、孔洞、属性和高度送入独立GeoJSON备用图层。只有剩余组件完成加载及后续渲染后，才隐藏原瓦片要素。实际瓦片要素23809960包含46个组件；回归测试仅覆盖外滩18号时，移除该组件，其余45个逐坐标保留。相同的重复瓦片组件去重，不剪裁、拼接或推测重叠碎片。

跨出完整覆盖范围的单个Polygon、缺少ID或来源几何无法确认的要素继续保留；退出覆盖、加载失败、来源替换或备用图层丢失时恢复原要素。不同来源的轮廓、年代与部件分组并不完全相同，因此这是保守的备用显示处理，不宣称跨来源逐栋测绘一致。边界组件仍可能与本地模型部分重叠。

另将碰撞缓存提前初始化，修复服务快速失败时触发的Cannot access collisionDirty before initialization。57项专门测试检查凹多边形、孔洞、重复瓦片片段、数字/文字ID、真实46组件案例、异步渲染确认、加载失败、移出覆盖、备用图层丢失和状态移除重试。浏览器另行模拟Overture与版本目录同时不可用，验证外滩第三人称和长宁屋顶视角，并检查23809960被隐藏且剩余组件不再包含外滩18号中心；结果见项目tests中的最终回退验证记录。

软件渲染浏览器实测约0.30 FPS时，原6秒更新期限不足以等待多轮渲染，模型已全部加载仍触发超时。现期限为30秒，就绪条件保持不变，等待期间原建筑保持可见。[复现证据](slow-renderer-regression.json)与最终浏览器记录分开保存。
