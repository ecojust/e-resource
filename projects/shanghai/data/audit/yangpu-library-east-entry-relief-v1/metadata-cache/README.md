# 原有地标修订后的目录缓存

杨浦区图书馆在地图中一直使用 `yangpu-library`。东门修订沿用了该入口，更新了整馆GLB和原有普通模型的登记。Chromium实测表明，仅给新版应用入口换地址时，地图仍可能采用浏览器保存的V13登记。按发布版本请求启动清单，并给普通JSON请求附上已有内容签名后，旧缓存中的四个目录仍可保留，同一浏览器能登记并下载修订版。[五种真实缓存状态及HTTP收据](actual-http.json) · [修正后的冻结站点再次实测](frozen-site-http.json)

| 已预热的旧资源 | 新版入口的实测结果 |
| --- | --- |
| 地标清单、精模主配置、普通总目录、分区索引 | 登记并校验了旧版整馆，6,622,720字节，SHA-256以 `33efb74e` 开头 |
| 普通总目录、分区索引 | 新配置预期的 SHA-256 与缓存的普通总目录不符，核验停止 |
| 分区索引 | 新总目录登记的字节长度与缓存索引不符，宏区登记停止 |
| 地标清单 | 真实场景登记适配器拒绝把新版宏区记录与旧导航记录合并 |
| 四件旧缓存，使用修正代码 | 成功登记并校验含东门的新整馆，7,829,672字节，SHA-256以 `05e7dc5f` 开头 |

每种情况使用单独的Chromium缓存。测试站先提供前一版本文件并设一天有效期，再在同一来源供应新版入口。试验直接执行该入口中的实际启动请求，调用正式普通目录读取器、宏区加载器和场景登记适配器，并校验完整GLB的格式、长度和签名。浏览器资源表和服务器接收的请求共同区分了缓存命中与网络传输。模型几何的真实 WebGL 前后对照另见本栋审计目录。[缓存复验程序](warm-http.cjs) · [原有37项回归结果](ordinary-tests.log) · [整馆几何与独立渲染](../README.md)

## 复跑

需要 Node、Playwright 和 Chromium。每个参数可传站点的 `projects/shanghai` 本地目录，也可传以斜线结尾的 HTTP(S) 站点根地址。`--old` 为修改模型之前的站点。`--new` 为含修订资产而尚未修正缓存读取的站点。`--fixed` 为同一修订采用新缓存处理后的站点。测试从 `--fixed` 读取三个实际模块，从 `--new` 读取其余数据和模型。输出目录需为新目录。

```sh
node warm-http.cjs \
  --old "$OLD_SHANGHAI_SITE" \
  --new "$REVISED_SHANGHAI_SITE_BEFORE_CACHE_FIX" \
  --fixed "$FIXED_SHANGHAI_SITE" \
  --out "$NEW_RESULT_DIRECTORY"
```

稀疏签出可用 `--assets` 提供缺失文件所在的站点；也可用 `--old-glb` 和 `--new-glb` 显式提供两代近景GLB的文件或URL。请用 `--chromium` 或环境变量 `CHROMIUM_PATH` 选择浏览器。`actual-http.json` 保留实际访问请求、正式资产SHA-256、三个模块的前后签名和程序自身的签名。
